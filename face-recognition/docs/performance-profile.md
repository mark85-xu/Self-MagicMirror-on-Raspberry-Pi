# C++ 运行时耗时与内存剖析（2026-11-13）

环境为当前 Raspberry Pi 5、4GB 内存、NCNN 与 OpenCV 均 4 线程。输入沿用部署验收中的 60 帧、640×480 单人 MJPEG 视频；检测网络输入为 640×640，每帧执行检测、对齐、特征提取和比对。

## 帧率限制

使用相同 C++ 核心模块进行分段计时，前 5 帧作为预热。无窗口模式的均值：

| 阶段                             |  平均耗时 | 占比（近似） |
| -------------------------------- | --------: | -----------: |
| 视频读取/解码                    |  1.923 ms |         1.6% |
| 检测整体：预处理、NCNN、解码/NMS | 87.233 ms |        74.0% |
| 五点对齐、SFace 特征提取与归一化 | 28.792 ms |        24.4% |
| 原向量库余弦比对                 |  0.002 ms |       <0.01% |

探针整段帧率为 8.441 FPS；未改动的主程序复核为 8.437–8.485 FPS，接近此前验收的 8.526 FPS。以上检测耗时包含整个 `Detector::detect()`，覆盖预处理、网络前向和后处理三个环节。

预览模式另测得画框/标签约 0.364 ms、窗口显示/事件处理约 3.477 ms（均为预热后均值）；首次创建窗口会引入更大的一次性开销。开启预览后，检测阶段也出现额外耗时，因此最终显示帧率使用开启预览后的完整循环实测。

采集当前配置了 15 FPS 上限。目前单人计算耗时先限制了速度；只有计算加速到足够快后，采集上限才会成为下一处限制。多人时检测仍执行一次，但 SFace 需要逐人执行，额外人脸会继续增加特征提取时间。

## 主程序内存

另启动原始 `face_recognizer`，从其 `/proc/<pid>/status` 周期读取内存指标，稳定 RSS 为运行 2 秒后的采样中位数：

| 模式   |  稳定 RSS |  峰值 RSS | 本进程 Swap |
| ------ | --------: | --------: | ----------: |
| 无窗口 | 203.1 MiB | 237.2 MiB |           0 |
| 有预览 | 276.9 MiB | 276.9 MiB |           0 |

RSS 包括映射进进程的共享库页。表中使用测试视频；实际 CSI 场景的内存评估还包括 DMA/CMA 和 ISP 驱动缓冲。

分阶段内存探针显示：

- 基础运行库和初始化状态约 75 MiB RSS。
- 加载 NCNN 后约 89 MiB；加载 SFace 后约 150 MiB，SFace 加载期间的瞬时峰值约 231 MiB。
- 首次推理分配中间张量、工作区和缓存后，探针无窗口 RSS 约 197 MiB，前 5 帧后至第 60 帧保持稳定。
- Qt 预览在该探针中增加约 74 MiB RSS，其中包含共享库、字体及显示相关分配。

该组件探针没有链接主程序的相机模块，RSS 比真实主程序低约 6 MiB；上表采用主程序直接测量值。阶段增量包含分配器缓存和库页加载，分析模型内存时应结合这些共享和缓存开销。

5 条 128 维 float32 向量本体仅为 `5×128×4=2560` 字节，约 2.5 KiB；姓名和归档解析有额外小开销。它们不是当前内存或计算瓶颈。640×480 的单张 BGR 图像约 0.88 MiB，640×640×3 的 float32 输入张量约 4.69 MiB。

## 后续优化优先级

1. 首先评估检测输入从 640 降至 416/320 的收益；需要重新导出 NCNN，并验证五点和身份相似度精度。
2. 引入可靠的人脸跟踪后，按需或间隔提取身份特征，减少逐帧 SFace 计算。
3. 如需稳定预览，可将推理与 UI 主线程解耦，并评估显示后端与刷新策略。

当前应优先优化计算与调度，而不是压缩只有几 KiB 的向量库。测试时没有发生 CPU 降频，本进程没有换出；内存容量不是本次帧率的首要限制。
